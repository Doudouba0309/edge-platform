The 30-second version

If you only do five things, do these:

  1. make check — the code is healthy.
  2. make verify — the collector works with real certificates and survives an outage.
  3. make smoke — the image builds, boots and publishes.
  4. Run the collector locally and see ok / ready.
  5. Open the AWS MQTT test client, subscribe to edge/#, and watch a reading arrive.
  6. Optionally inspect the JSON logs, status heartbeat and support bundle.
1. ImageBoots and runs
2. CollectorCollects and packs
3. NucleusSends securely
4. AWSReceives data
This guide is read-only in AWS. It does not create, change or delete anything. It only builds locally, runs local containers, lists AWS resources, and subscribes to a topic.

Words in plain English

WordWhat it means here
ImageA prebuilt box containing the operating system, Python and the collector. It is what runs on the gateway.
CollectorThe program that reads sensors, packs readings into batches, and hands them to the sender.
Nucleus / GreengrassThe local “postmaster”. It owns the gateway certificate, the secure AWS connection and the offline queue.
ComponentAn installable piece of software managed by the postmaster. Our collector is one component.
IoT CoreThe AWS mailbox that receives the telemetry.
TelemetryOne parcel of readings, with a gateway id, device id, timestamp and values.
SpoolThe local outbox. If the connection is down, batches wait there and are sent later.

Before you start

TerminalOpen a terminal in the repository root.
DockerDocker Desktop must be running for image and mTLS tests.
AWS CLIProfile edge-platform-admin, region ap-southeast-1.

Prepare the local environment once:

make install

If Docker is not running, start Docker Desktop and wait for the whale icon to settle.

Current sandbox only. The AWS checks expect the test resources named below. If the sandbox was torn down, set it up again first; this guide does not create resources.
1
The image

Build it, boot it, make it publish

3–6 minutes on the first run; faster afterwards.

This test builds the actual gateway image, starts it, waits for readiness, subscribes to the local broker, checks the telemetry schema, checks memory, and stops the container cleanly. 

make smoke

On an Apple Silicon Mac, testing just one architecture is faster:

PLATFORMS=linux/arm64 make smoke

On an Intel machine, use:

PLATFORMS=linux/amd64 make smoke
PASS: arm64 boot, mutual TLS, schema, RSS, SIGTERM
PASS: linux/arm64
The command exits with status 0.

You can also confirm the image exists:

docker image ls | grep edge-platform-base

You should see edge-platform-base:arm64 and/or edge-platform-base:amd64.

What this proves. The image is not just “buildable”; it boots, starts the collector, publishes valid telemetry over mutual TLS, stays under the memory limit, and shuts down without hanging.
2
The collector

Test the code, then run it by hand

1–2 minutes, plus a few seconds of running.

2A. Fast code check

make check
Ruff and mypy report no issues; all unit tests pass (145 passed at the time of writing).

2B. Run the collector locally

This uses a pretend sensor and the log sink, so nothing leaves your machine. Leave it running and use a second terminal for the checks. 

.venv/bin/edge-collector --config config/collector.yaml

You should see lines like these:

INFO edge_collector.sinks.log: log sink ready
INFO edge_collector.health: health endpoint listening on http://127.0.0.1:8081/healthz
INFO edge_collector.sinks.log: batch #1 device=plc-line-1 samples=2 bytes=526

In a second terminal, ask the collector how it is doing:

curl -s http://127.0.0.1:8081/healthz
curl -s http://127.0.0.1:8081/readyz
curl -s http://127.0.0.1:8081/stats
healthz → ok
readyz → ready
/stats → JSON with "sink": {"name": "log", "healthy": true} and a non-zero "batches_sent".

Stop the collector with Ctrl+C. It should exit promptly.

2C. Test the real transport

This starts a local broker that demands a client certificate, runs the collector against it, breaks the connection, and confirms the spool replays. 

make verify
spooled while offline: … batch(es)
PASS: mutual TLS telemetry, schema, outage, replay, RSS … KB, SIGTERM
What this proves. The collector does not merely log: it authenticates with a certificate, publishes valid batches, buffers during an outage, and drains the outbox in order when the broker returns.
2D
Evidence for remote support

Check logs, status and the support bundle

1–2 minutes, after `make smoke`.

The live AWS component is 1.0.9 and includes the supportability slice. These checks use the local image smoke for the fastest evidence; the same status is now visible in AWS.

2D-1. Confirm the shipped log is structured

Pick the architecture you tested and inspect the first two lines:

ls var/smoke-image

head -2 var/smoke-image/arm64-collector.log

Use amd64-collector.log if you tested x86_64.

JSON lines with ts, level, logger, message, gateway_id and service_version.

2D-2. Confirm online/offline status

grep '"state"' var/smoke-image/arm64.jsonl | head -2
One record with "state": "online" and one with "state": "offline" on edge/dev-gateway-01/status. The payload is JSON and includes event, version, ready, sources, sink and spool_pending.

2D-3. Build and inspect a support bundle

.venv/bin/edge-collector-support \
  --config config/collector.yaml \
  --log-file var/collector.log \
  --output var/validation/support-bundle.zip

unzip -l var/validation/support-bundle.zip
The ZIP contains manifest.json, config.yaml, system.json and logs/collector.log. It must not contain private keys, passwords or tokens.
Why this matters for a remote client. These are the artefacts you can ask the client to send when something fails: the log, the gateway state and a redacted configuration snapshot — without needing a shell on the gateway.
Now live in AWS. Component 1.0.9 publishes status and heartbeat on edge/edge-platform-sandbox-core/status. The local image smoke is still the quickest way to inspect the raw JSON logs.
3
The data in AWS

Confirm the gateway, the component and the message

2–3 minutes, plus about 10–15 seconds of waiting.

3A. Is the test gateway alive?

aws sts get-caller-identity --profile edge-platform-admin

aws greengrassv2 list-core-devices \
  --region ap-southeast-1 \
  --profile edge-platform-admin
Your account id and the edge-platform-admin identity.
Core device edge-platform-sandbox-core has status HEALTHY.

3B. Is the collector installed and running?

aws greengrassv2 list-installed-components \
  --core-device-thing-name edge-platform-sandbox-core \
  --region ap-southeast-1 \
  --profile edge-platform-admin
Component io.github.doudouba0309.EdgePlatform.Collector
Version 1.0.9 is the live component and includes supportability.
lifecycleState: RUNNING

3C. See the message in AWS

  1. Open the AWS IoT Core console in region ap-southeast-1.
  2. Go to Test → MQTT test client.
  3. Under Subscribe to a topic, enter edge/#.
  4. Choose Subscribe.
  5. Wait 10–15 seconds.

You should see a message on:

edge/edge-platform-sandbox-core/plc-line-1/telemetry

The payload should look like this:

{
  "schema_version": "1.0",
  "gateway_id": "edge-platform-sandbox-core",
  "device_id": "plc-line-1",
  "seq": 20,
  "samples": [
    {
      "device_id": "plc-line-1",
      "metric": "temperature",
      "value": 23.5,
      "ts": "2026-10-17T12:57:51.928279+00:00",
      "source": "sim",
      "origin": "synthetic:temperature",
      "unit": "degC",
      "quality": "good",
      "tags": {}
    }
  ]
}
schema_version is 1.0;
gateway_id is edge-platform-sandbox-core;
device_id is plc-line-1;
at least one sample with quality: "good".

3D. Optional — use the terminal instead of the console

If the sandbox certificate files are present:

source certs/sandbox/env.sh

mosquitto_sub \
  -h "$IOT_DATA_ENDPOINT" -p 8883 \
  --cafile certs/sandbox/AmazonRootCA1.pem \
  --cert certs/sandbox/observer.cert.pem \
  --key certs/sandbox/observer.private.key \
  -i edge-platform-sandbox-observer \
  -t 'edge/#' -C 1 -W 60 -v

If the certs are missing, use the console test client. It needs no certificate.

3E. Optional — look at the local core

docker ps | grep edge-platform-aws-core

docker logs --tail 30 edge-platform-aws-core

docker exec edge-platform-aws-core \
  tail -40 /greengrass/v2/logs/io.github.doudouba0309.EdgePlatform.Collector.log

The component log should show the IPC sink ready and batches being published, with no repeating authorization errors.

What this proves. The data did not stop at a log file or a local broker. It went from the collector, through the Greengrass nucleus and mutual TLS, into AWS IoT Core.

What success looks like

  • make check passes.
  • make verify prints a PASS line that mentions mutual TLS, outage and replay.
  • make smoke prints PASS for the architecture you tested.
  • The local collector returns ok and ready, and its stats show a healthy sink.
  • The AWS core is HEALTHY.
  • The collector component is RUNNING.
  • The MQTT test client shows a valid batch on edge/edge-platform-sandbox-core/plc-line-1/telemetry.
  • The image smoke shows JSON logs and an online/offline status pair.
  • The support bundle opens and contains no secret material.
If the first four pass but AWS shows nothing, the problem is in the AWS path (core, component, policy or subscription), not in the collector code. Check part 3A and 3B before changing code.

If something fails

SymptomWhat to check
Cannot connect to the Docker daemonStart Docker Desktop and wait until it is ready.
mosquitto_pub: command not foundInstall the Mosquitto clients: brew install mosquitto.
make smoke takes a long timeThe first build downloads the base image and builds two architectures. Use PLATFORMS=linux/arm64 make smoke for a shorter run.
Local collector exits immediatelyRun make install, then check the log for a config error. The default config is config/collector.yaml.
/readyz returns 503The synthetic source is not connected yet. Wait a second and retry; check the collector log.
AccessDenied or ExpiredToken from AWSConfirm aws sts get-caller-identity --profile edge-platform-admin works and the region is ap-southeast-1.
Core is not HEALTHYCheck docker ps and docker logs edge-platform-aws-core. The core may have been stopped or the sandbox torn down.
Component is not RUNNINGCheck the deployment and the component log. A failed deployment may have rolled back.
No MQTT messagesConfirm the subscription is edge/#, the region is ap-southeast-1, and the component is running. Wait 15 seconds; batches are periodic.
Messages are visible but malformedRun make check; the schema contract tests catch most of this. Check the payload against the example in part 3C.
Logs are plain text, not JSONLocal config/collector.yaml is intentionally text. Inspect var/smoke-image/*-collector.log for the container's JSON logs.
No status records in the image smokeCheck var/smoke-image/*.jsonl; the live 1.0.9 AWS component now includes status; check the AWS MQTT test client as well.
Support bundle command not foundRun make install after pulling this change, or use .venv/bin/python -m edge_collector.support ....

Safety notes

Do not use root AWS credentials. Use the named edge-platform-admin profile. Never paste access keys or certificate private keys into chat, a document or a ticket.
This guide does not tear anything down. The test core, certificates, role and component versions are still live in the sandbox. Teardown is a separate, destructive action and needs explicit confirmation.
