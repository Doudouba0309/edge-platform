Part 4

Rebuild it on your own machine

This part takes you from a fresh clone to a working collector, a tested image and a packaged Greengrass component. No AWS account is required.

How to use this part. Copy one command block at a time. Wait for it to finish. Compare the output with the “expected” box before moving on. If something fails, jump to Part 6.

What you are building

You are not just installing Python packages. You are building a small chain:

Each step has a visible finish line. If a command prints an error, stop there; do not continue to the next step hoping it will fix itself. Part 6 explains the common failures.

Terms you will meet

TermWhat it means
Virtual environmentA private folder for this project’s Python packages, so it does not interfere with the rest of the computer.
Ruff / mypy / pytestThree checks: formatting and style, type consistency, and behaviour tests.
mTLSMutual TLS: both sides present a certificate, so the collector and broker can prove who they are to each other.
ImageA prebuilt box with the OS, Python and collector, ready to run on a gateway.
ComponentAn installable Greengrass package containing the collector and its recipe.
WheelhouseA folder of Python packages bundled for offline installation on the gateway.

On macOS, install the missing tools with Homebrew:

brew install uv mosquitto
brew install --cask docker

Open Docker Desktop once and wait until it says it is running.

2. Get the repository

git clone https://github.com/Doudouba0309/edge-platform.git
cd edge-platform

You are in the repository root when ls shows Makefile, src/, docs/ and Dockerfile.

3. Create the Python environment

make install

This creates .venv/ and installs the runtime plus the development tools. It is safe to run again; it reuses the existing environment.

What “environment” means. A private folder of Python packages for this project. It keeps the project’s libraries separate from the rest of your computer.

4. Run the fast checks

make check

This runs four things:

  1. Ruff — formatting and lint rules.
  2. mypy — strict type checking.
  3. pytest — the unit and contract tests.
  4. Secret guard — fails if a tracked file looks like a key or credential.
Expected. Ruff and mypy report no issues, and pytest prints 147 passed (the number can grow as tests are added). The secret guard prints clean.

5. Run the collector by hand

The default configuration uses a synthetic sensor and the log sink. Nothing leaves your computer. 

.venv/bin/edge-collector --config config/collector.yaml

Leave it running. In a second terminal, ask it three questions:

curl -s http://127.0.0.1:8081/healthz
curl -s http://127.0.0.1:8081/readyz
curl -s http://127.0.0.1:8081/stats
Expected. ok from /healthz, ready from /readyz, and JSON from /stats with a healthy log sink and a non-zero batches_sent.

In the first terminal, you should see a line like:

INFO edge_collector.sinks.log: batch #1 device=plc-line-1 samples=2 bytes=526 sources=['sim']

Stop it with Ctrl+C. It should flush and exit promptly.

If you see “address already in use” on port 8081. Another collector is already running. Find it with lsof -nP -iTCP:8081 -sTCP:LISTEN, stop that process, and run the collector again.

6. Test the real transport, outage and replay

make verify

This is the most important collector test. It starts a local Mosquitto broker that requires a client certificate, runs the collector against it, stops the broker, confirms the batch is spooled, restarts the broker and confirms the batch is replayed.

Expected. spooled while offline: 1 batch(es) and a final line beginning PASS: mutual TLS telemetry, schema, outage, replay, RSS ….

7. Build and boot the image

The image is the bottom layer: Ubuntu 24.04, Python 3.12, the collector and a non-root user. This test builds it, boots it, publishes over mutual TLS, validates the schema, checks memory, and stops it. 

make smoke

On Apple Silicon, a faster single-architecture run is:

PLATFORMS=linux/arm64 make smoke

On Intel:

PLATFORMS=linux/amd64 make smoke
Expected. PASS: arm64 boot, mutual TLS, schema, RSS, SIGTERM (and/or the amd64 line), then PASS: linux/arm64 …. The first run can take several minutes because it builds base layers.

Inspect the image afterwards:

docker image ls | grep edge-platform-base
docker history edge-platform-base:arm64 | head -20

8. Build the Greengrass component

GG_BUCKET=edge-platform-sandbox-<account-id>-ap-southeast-1 \
GG_ACCOUNT_ID=<account-id> \
GG_THING_NAME=edge-platform-sandbox-core \
GG_ROLE_ALIAS=edge-platform-sandbox-TESRoleAlias \
make component

This builds a wheel for the collector, downloads Linux wheels for arm64 and x86_64, zips them, and renders the recipe and IoT policy.

Expected. build/component/EdgeCollector-1.0.12.zip (about 14 MB), recipe.yaml and iot-policy.json.

Inspect what was produced:

ls -lh build/component
unzip -l build/component/EdgeCollector-1.0.12.zip | head -20
grep -n -A6 'accessControl' build/component/recipe.yaml

The version may change when a new immutable component version is published. The build script default is the latest version in the repository.

9. Optional: prove the nucleus still works offline

make nucleus-smoke

This builds the nucleus image for both architectures and checks startup, the IPC socket, identity reuse across a restart, and clean SIGTERM. It needs Docker and is slower than the collector tests.

Expected. PASS: arm64 nucleus launch, IPC, identity reuse, SIGTERM and the equivalent amd64 line.

10. Optional: build the software inventory

make sbom

This generates CycloneDX SBOMs with Syft for the collector images. It is optional for a rebuild, but it is part of the CI evidence. Run make sbom-nucleus for the nucleus images.

What each step proved

StepWhat it provedWhat it did not prove
Fast checksThe code is internally consistent and the contract tests pass.That a real broker or image works.
Run by handThe collector starts, reads config and serves health.That TLS or AWS works.
mTLS/outage testCertificates work, batches spool and replay in order.That the AWS core or component deployment works.
Image smokeThe actual image boots and publishes on both architectures.That the Greengrass component installs.
Component buildThe recipe, wheelhouse and policy are internally consistent.That AWS accepts or runs them.

What you have now

  • A working Python environment and a passing test suite.
  • A collector that can log, publish over mTLS, spool and replay.
  • A bootable Tier 1 image.
  • A Greengrass component artifact, recipe and policy.
  • No AWS account required.
Do not skip make verify. make smoke proves the image; make verify proves the outage/replay behaviour that makes the gateway useful on a real solar site network.
