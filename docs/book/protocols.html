Reference · protocols

Industrial protocols, without the mystery

A protocol is an agreement about how to ask a device a question and how to understand the answer. This chapter explains the protocols in the SOW and the gateway roadmap, what each one is good at, and what it is not.

Read this first. No protocol is “best”. Each was designed for a different job. Modbus is simple and everywhere; OPC UA is structured and secure; MQTT is a publish/subscribe transport; IEC 60870-5-104 and DNP3 are utility SCADA protocols; REST is a web API. The point map turns any of them into the same Sample.

2. Modbus RTU and Modbus TCP

Modbus is the industrial equivalent of a short, simple phrasebook. It was published in 1979 and is still everywhere because it is easy to implement and easy to inspect.

The data model

Data typeWidthMeaningRead function
Coil1 bitReadable/writable on/off state01
Discrete input1 bitRead-only on/off state02
Input register16 bitRead-only value04
Holding register16 bitReadable/writable value03

A 32-bit number or a float occupies two consecutive registers. The order of those two registers (word order) and the byte order inside each register are vendor choices. Getting them wrong produces a plausible but wrong number.

RTU vs TCP

Modbus RTUModbus TCP
PhysicalRS-485 (usually), sometimes RS-232Ethernet / IP
AddressingSlave/unit id 1–247 on the busIP address + port 502; unit id in the MBAP header
FramingBinary frame + CRCMBAP header + protocol data unit
TimingBaud, parity, inter-frame silenceNetwork latency and TCP connection behaviour
Typical useInverters, meters, PLCs on a serial trunkPlant LAN, gateway-to-device, SCADA
Common failuresA/B swapped, wrong baud, no termination, wrong slave idWrong IP/port, firewall, unit id, connection limit
Addresses are a trap. A vendor document may show “40001” or “40100”. That is usually a human-readable reference, not the number sent on the wire. The wire often uses a zero-based offset. The point map must record the convention instead of guessing.

In this platform: Modbus TCP is the first implemented source (solar, 1.0.12). Modbus RTU is planned for the next slice, with a USB-RS485 adapter and hardware-in-the-loop testing.

3. OPC UA

OPC UA is a richer industrial protocol. Instead of raw registers, a server exposes a structured address space of nodes. Each node has a node id, type, value, timestamp and status code.

ConceptPlain English
EndpointThe URL of the server, e.g. opc.tcp://192.0.2.10:4840.
Node idThe address of one value, e.g. ns=2;s=Inverter1.Power.
SessionA secured, stateful connection between client and server.
SubscriptionThe server sends changes instead of the client polling each value.
StatusCodeGood, uncertain or bad, with a reason.
SecurityCertificates, signing and encryption are built into the protocol.

OPC UA is not “better Modbus”. It is a trade-off: more structure, security and metadata, but a heavier server and more configuration. Many modern PLCs expose it; many small inverters do not.

4. OPC DA — the older Windows protocol

OPC DA (Data Access) is the predecessor to OPC UA. It relies on Microsoft COM and DCOM, so it is tied to Windows and is awkward across firewalls and networks. It is still found in older SCADA and historian installations.

Do not expose DCOM to the internet. If a site only has OPC DA, the usual approach is a local Windows gateway or an OPC DA-to-OPC UA wrapper. The edge collector should not depend on DCOM or a Windows runtime. OPC DA is a compatibility problem, not a first-choice integration.

5. MQTT

MQTT is a publish/subscribe protocol built around a broker. Devices publish to topics; subscribers receive matching messages. It is excellent for the northbound path and for gateways that already aggregate data.

ConceptMeaning
BrokerThe server that receives and distributes messages.
TopicA hierarchical address, e.g. edge/site/inv-01/telemetry.
QoS 0/1/2At most once / at least once / exactly once delivery semantics.
Retained messageThe broker keeps the last message for a new subscriber.
Last WillA message published by the broker if a client disappears.

MQTT does not define registers, coils, node ids or units. It is a transport for data that is already structured. The project uses MQTT for the northbound telemetry path, not as a replacement for Modbus or OPC UA.

6. IEC 60870-5-104

IEC 60870-5-104 (“IEC 104”) is a utility SCADA protocol used to monitor and control substations and grid assets over TCP. It carries ASDUs (application service data units) with a common address, information object address, type identifier and value.

  • Physical: TCP/IP, usually port 2404.
  • Model: controlling station and controlled station.
  • Data: status points, measurements, counters, commands and events.
  • Typical use: grid interconnection, substations and utility dispatch.
  • Not typical: a small solar inverter’s internal telemetry.

It may be relevant at the grid meter or interconnection layer, not at the inverter. It is not implemented in this phase and should not be confused with Modbus.

7. DNP3

DNP3 (Distributed Network Protocol) is another utility SCADA protocol, common in electricity, water and oil-and-gas networks. It uses a master/outstation model, objects and variations, and event buffers.

  • Physical: TCP/IP, usually port 20000, or serial.
  • Model: master and outstation.
  • Data: binary inputs, analog inputs, counters, outputs and events.
  • Security: DNP3 Secure Authentication exists but is not universal.
  • Typical use: utility remote monitoring and control.

Like IEC 104, DNP3 belongs to the grid/utility edge, not the inverter’s Modbus register map. It is not implemented yet.

8. REST APIs

A REST API is a web interface: the client sends an HTTP request and receives JSON (usually). Vendor cloud APIs — for example a Huawei FusionSolar portal — are often REST, not Modbus.

StrengthWeakness
Easy to integrate, well documented, works through HTTPSNot real-time; rate limits; pagination; cloud dependency
Good for fleet-level and vendor portalsOften minutes behind, not suitable for fast control or fault capture
JSON is easy to inspectAuthentication and API changes are vendor-specific

REST is a useful later source for vendor-cloud data, but it is not a substitute for a local Modbus/OPC UA connection when the site needs full-resolution data.

The protocol adapter is allowed to know about Modbus or OPC UA. The rest of the system is not. That boundary is why a new protocol does not change the cloud contract, the spool or the dashboards.

11. Security rules that apply to every protocol

  • Read-only first. No writes or control commands in v1.
  • No inbound internet access. The gateway connects out; nothing connects in.
  • No credentials in the component. The nucleus owns the device identity.
  • Respect the OT network. Use the site’s firewall/VLAN rules; do not bypass them.
  • Never invent a register map. A wrong address can look like a valid measurement.
  • Count failures. A timeout is not a zero; it is bad quality.

12. What to ask a vendor

  • Which protocol and physical layer?
  • For Modbus: unit id, IP/port or serial settings, register map.
  • Address convention: reference number or zero-based offset?
  • Function code and data type for every point.
  • Byte order, word order, signedness, float vs integer.
  • Scale, offset, unit and rollover behaviour.
  • Which points are mandatory, optional, and how often they change.
  • A known-good capture or nameplate value to prove the interpretation.
  • Whether writes are needed (v1: no).
  • Any gateway, firewall or connection-limit constraint.
