Part 3

What was built, in the order it happened

The project was not built in one heroic commit. It was built in small slices, each with a finish line. This part is the honest build history and the map of what now exists.

The short version

Foundation

Repository, design documents, operating manual and a frozen data contract.

Runtime

Collector, batching, bounded queue, SQLite spool, health endpoints and mTLS MQTT.

Delivery

Base image, CI, SBOMs, offline nucleus, IPC sink, component package and AWS proof.

The tests

At the time of writing, make check runs 167 tests. They cover models, schema drift, identifiers, config, synthetic source, batching, queue overflow, spool ordering and budgets, sink failure/reconnect, health, app wiring and the AWS artifact contract.

The delivery pieces

  • Dockerfile — the pinned Ubuntu 24.04 base, non-root collector image.
  • nucleus/Dockerfile — Ubuntu 24.04, OpenJDK 17, nucleus 2.18.4 and, after the AWS proof, Python 3.12 + venv.
  • nucleus/entrypoint.sh — offline self-signed mode or AWS mode with mounted certificates.
  • deploy/greengrass/recipe.yaml.tmpl — component recipe, two architectures, lifecycle and IPC access control.
  • deploy/aws/iot-policy.json.tmpl — core IoT policy template.
  • scripts/build-component.sh — wheelhouse, ZIP, rendered recipe and policy.
  • scripts/smoke-image.sh, smoke-local.sh, smoke-nucleus.sh — the three smoke tests.
  • scripts/sbom.sh — CycloneDX SBOM generation.
  • scripts/gen-test-certs.sh — local test PKI.
  • scripts/check-secrets.sh — tracked-path and content guard.

The operations and security pieces

  • Makefile — install, hooks, format, lint, test, check, component, verify, smoke, SBOM and nucleus smoke.
  • .github/workflows/ci.yml — check, component package, Tier 1 images and nucleus; buildx cache; docs-only skip.
  • .github/workflows/security.yml — secret guard on every push, including docs-only changes.
  • .pre-commit-config.yaml — private-key detector and the local secret guard.
  • docs/ — proposal, roadmap, decisions, AWS setup guide, testing guide and this handbook.

The AWS proof, step by step

The code alone was not enough. The team provisioned a real test core and deployed the component. The proof took several attempts because each attempt exposed a different missing permission or a platform mismatch.

  1. Created a test thing, thing group and device certificate.
  2. Created an IoT policy for the core: MQTT topics, Greengrass control-plane calls and permission to assume the token exchange role.
  3. Created the TES role with a trust relationship for credentials.iot.amazonaws.com, plus an inline policy for IoT, logs, S3 object read and bucket location.
  4. Created the role alias that the nucleus asks for credentials.
  5. Built the nucleus image with Python 3.12 and venv, because the component installs its own Python environment.
  6. Ran the core with the certificate, key, Amazon root CA and the correct data/credentials endpoints.
  7. Built the component ZIP with Linux wheels for arm64 and x86_64; uploaded it to S3.
  8. Created the original component version 1.0.4 and deployed it.
  9. Subscribed with a read-only observer certificate and saw a real batch arrive.
The observed proof. Component io.github.doudouba0309.EdgePlatform.Collector version 1.0.4 was the original proof; the current live component is 1.0.10 and is RUNNING on edge-platform-sandbox-core, and a schema-1.0 batch arrived on edge/edge-platform-sandbox-core/plc-line-1/telemetry.

What is still only a promise

  • Reading a real OPC UA server or Modbus PLC.
  • A repeatable, scripted AWS provision/publish/deploy/teardown flow.
  • Production hardening, fleet provisioning, certificate rotation and support.
  • Teardown of the current sandbox.
