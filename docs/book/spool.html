The spool: an outbox that survives a power cut

The queue protects memory. The spool protects data across a crash, a power cut or a long uplink outage. It is deliberately small, boring and durable.

The promise. Once a batch is accepted into the spool, it survives a process restart and is replayed oldest-first when the sink returns. The collector may duplicate a batch after a crash; it must not silently lose one.

Why not keep everything in memory?

The in-memory queue is bounded. If the internet is down for six hours, a queue of a few thousand samples cannot hold the data. RAM is also the first thing lost in a power cut.

The spool writes each batch to local disk as a SQLite row. SQLite in WAL mode is crash-safe, needs no extra service, and is well understood on small Linux devices.

The lifecycle

  1. The pipeline builds a Batch.
  2. The sink is available and the spool is empty: send directly.
  3. The sink is unavailable or a backlog exists: append the batch to the spool.
  4. The replay loop reads the oldest rows, sends them, and deletes only the rows that were successfully sent.
  5. New batches queue behind any existing backlog. Nothing overtakes it.

The database

CREATE TABLE spool (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    created_at REAL    NOT NULL,
    payload    BLOB    NOT NULL
);

CREATE INDEX spool_created_at ON spool (created_at);

id is the FIFO order. created_at is diagnostic. payload is the exact JSON batch bytes, not a Python object. The schema is intentionally tiny.

Power-cut behaviour

EventWhat happens
Process crashCommitted rows remain; replay resumes on next start.
Power cutWAL recovery restores committed rows. The last few uncommitted writes may be lost; that is the normal durability boundary.
Crash after send, before deleteThe batch may be sent again. This is at-least-once, not exactly-once.
Corrupt payloadThe row is dropped, counted as spool_corrupt_dropped, and the rest continues.
Disk fullAppend fails; the batch is counted as lost and the error is logged.
Old backlogOldest payloads are purged to stay under the byte budget.

The budget is bytes, not file size

SQLite does not return freed pages to the filesystem promptly. A file-size budget would delete a huge amount of data while the file still looked large. The spool therefore measures the sum of payload bytes.

  • spool.max_bytes is the payload budget.
  • Enforcement starts only when buffered bytes exceed the budget.
  • It deletes oldest rows until buffered bytes are below 90% of the budget.
  • It reclaims pages with PRAGMA incremental_vacuum.
  • If a single payload exceeds the budget, it is not reported as stored.

Ordering

The spool is the strongest ordering guarantee in the system. Once a row exists, new batches append behind it. The replay loop selects oldest first. The queue order is not a guarantee; the spool order is.

Batches are per device. Ordering is preserved within a device; different devices may be flushed in sorted device order.

Threading

The pipeline runs on an asyncio loop, but SQLite calls are blocking. They run in worker threads. The connection uses check_same_thread=False and every operation is serialised behind an RLock. This is not optional; SQLite connections are thread-affine.

A support bundle includes the spool summary, not the full payload history.

What the spool does not solve

  • It does not create disk space; a full disk still loses data.
  • It does not guarantee exactly-once delivery; retries may duplicate.
  • It does not sync to a second disk; a failed flash device can lose everything.
  • It does not replace a database or a data lake; it is a bounded outbox.
  • It does not preserve data if the process is killed before a row is committed.

Tests that pin the behaviour

  • Append, peek, delete and count.
  • Budget drops oldest payloads and never reports an oversized batch as stored.
  • Spool survives close/open.
  • Startup reports an existing backlog.
  • Replay sends oldest first.
  • A corrupt row is dropped and counted.
  • Sink failure spools, then replays.
  • WAL mode is enabled.
