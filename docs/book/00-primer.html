Hardware and protocol fundamentals

A solar inverter is a computer with an electrical job. To read it, you need to know which physical wire or network it uses, what language it speaks, and what its numbers mean. This primer explains those pieces in plain English before the design chapter uses them.

The one-sentence version. A protocol is an agreed way to ask a device a question and interpret its answer; the point map records which questions matter and how to turn the answers into named measurements.

1. The layers, from wire to metric

LayerQuestion it answersExamples
PhysicalWhat cable, connector or radio carries the bits?RS-485 pair, Ethernet cable, Wi-Fi, cellular
TransportHow are bytes framed and addressed?Modbus RTU over serial, Modbus TCP over Ethernet
ApplicationWhat does the device expose and what does the answer mean?Modbus registers, OPC UA nodes, MQTT topics
SemanticWhat is the measurement called and in what unit?ac_power_kw in kW; a fault code

Most integration failures happen at a boundary between layers. The cable may be fine but the baud rate wrong; the network may work but the register address is off by one; the value may arrive but the byte order makes it nonsense.

2. RS-485 is wiring, not a protocol

RS-485 is an electrical standard for a shared, twisted-pair serial bus. It says how devices put signals on the wire and how they take turns. It does not define what the bytes mean.

What it gives you

One pair of wires (A/B, sometimes labelled +/−) shared by several devices, often over hundreds of metres at low baud rates.

What it does not give you

No register map, no device names, no units and no automatic configuration. Those come from the protocol and the vendor documentation.

RS-485 is usually half-duplex: one device talks while the others listen. A master asks; a slave answers. Two devices must not transmit at the same time. This is why polling cadence and timeouts matter.

Practical RS-485 checklist

  • Daisy chain, not star. Keep a single trunk with short stubs.
  • Termination. Usually 120 Ω at both physical ends of a long bus; not at every device.
  • Bias. Some buses need fail-safe bias so an idle line is defined.
  • Ground and shield. Follow the vendor’s isolation and grounding rules; do not assume the shield is a signal return.
  • A/B labelling is inconsistent. If nothing answers, swapping A and B is a legitimate first test.
  • Baud, parity, data bits and stop bits must match. A common default is 9600 8N1, but it is not universal.
  • USB-RS485 adapters are not all equal. Some handle direction control automatically; some need a driver setting.

3. Modbus: the common language

Modbus is a simple request/response protocol. A client (often called a master) asks a server (slave) to read or write a small block of data. The server answers with values or an exception code.

Modbus is deliberately small. That is why it is everywhere, and why every vendor implements a slightly different corner of it.

Coils and registers

Data typeWidthTypical useRead function
Coil1 bitA readable/writable on/off state01
Discrete input1 bitA read-only on/off state02
Input register16 bitA read-only measurement04
Holding register16 bitA readable/writable value or setting03

A register is 16 bits — one unsigned number from 0 to 65535, or a signed number from −32768 to 32767. A 32-bit value, a float, or a 64-bit energy counter occupies two or four consecutive registers. The order of those registers is not universal.

Function codes you will meet

  • 01 — read coils.
  • 02 — read discrete inputs.
  • 03 — read holding registers.
  • 04 — read input registers.
  • 05/06 — write one coil/register. Out of scope for v1.
  • 15/16 — write multiple coils/registers. Out of scope for v1.

Exception responses are normal. A device may answer “illegal data address” if a register does not exist, or “server device failure” if it is busy. The collector must record these as bad quality, not silently keep the previous value.

4. Modbus RTU versus Modbus TCP

Modbus RTUModbus TCP
Physical layerRS-485 (usually), sometimes RS-232Ethernet / IP
AddressingSlave/unit ID on the bus, 1–247IP address and TCP port, usually 502; unit ID still exists in the header
FramingBinary frame with a CRCMBAP header plus protocol data unit; TCP provides integrity
TimingBaud rate, parity, inter-frame silenceNetwork latency and TCP connection behaviour
Typical useField devices, inverters, meters, PLCs over a serial trunkPlant LAN, gateway-to-device, SCADA
Failure modeWrong baud/parity, A/B swap, termination, slave IDWrong IP/port, firewall, unit ID, connection limits

The application data — registers, function codes, scaling — is conceptually the same. This is why a point map can target both, with a different connection block.

5. Addresses are a minefield

Vendor documents often show a “reference” such as 40001 or 40100. That is usually a human-readable convention, not the number sent on the wire.

Documentation saysWhat the wire often uses
Holding register 40001Offset 0
Holding register 40100Offset 99
Input register 30001Offset 0
Coil 00001Offset 0

Some documents show the offset directly, some show the one-based reference, and some show both. The point map must record which convention it uses. Guessing an address is how you read a completely different measurement and believe it.

6. Bits, bytes and word order

A 32-bit float is four bytes spread across two 16-bit registers. There are two independent choices:

  • Byte order inside each register (big-endian or little-endian).
  • Word order between the two registers (high word first or low word first).

A value can therefore be interpreted four ways. A plausible-looking number is not proof that the order is correct. Use a known value, such as a zero, a nameplate rating or a controlled test, to prove it.

Rule of thumb. If a value looks like a huge integer, a tiny fraction, or changes wildly with no physical cause, suspect word order or type before you suspect the sensor.

7. Scaling and units

Devices often expose integers with implied decimals. A register value 1234 may mean 123.4 V, 12.34 kW or 1234 kWh depending on the vendor. The point map records the transformation:

engineering_value = raw_value × scale + offset

A deadband suppresses tiny changes: if the last published value was 100.0 and the new value is 100.05, a deadband of 0.1 may intentionally filter it. Filtered is not the same as dropped, and the collector keeps that distinction visible.

8. Polling, timeouts and quality

A Modbus device answers when asked. The collector polls a block of registers, waits for an answer, and moves on. The important behaviours are:

  • Block reads. Ask for a contiguous range once, not one register per request.
  • Timeout. A missing answer is a failure, not a zero.
  • Retries with backoff. Do not hammer a device that is rebooting.
  • Quality. A timeout or exception produces quality: bad; a stale last value is not passed off as fresh.
  • Counters. Every failure is counted so support can see it.

Polling too fast can overload a small inverter or serial bus. Polling too slowly misses short events. The point map should make cadence explicit and reviewable.

9. OPC UA in one page

OPC UA is a richer industrial protocol. Instead of raw registers, a server exposes a structured address space of nodes. A node has a node ID, a data type, a value, a timestamp and a quality/status code.

ConceptMeaning
EndpointA URL such as opc.tcp://192.0.2.10:4840
Node IDThe address of one value, e.g. ns=2;s=Inverter1.Power
SessionA secured, stateful connection to the server
SubscriptionThe server sends changes instead of the client polling every value
StatusCodeGood, uncertain or bad, with a reason
SecurityCertificates, signing and encryption are part of the protocol

OPC UA is not “better Modbus”. It is a different trade-off: more structure and security, more configuration, and usually a heavier server. A site may expose both.

10. MQTT is not a fieldbus

MQTT is a publish/subscribe protocol built around a broker. Devices publish to topics; subscribers receive messages that match a topic filter. It is excellent for the northbound path and for gateways that already aggregate data.

ConceptMeaning
BrokerThe server that receives and distributes messages
TopicA hierarchical address such as edge/site-1/inverter-1/telemetry
QoS 0/1/2At most once / at least once / exactly once delivery semantics
Retained messageThe broker keeps the last message so a new subscriber sees it
Last WillA message the broker publishes if the client disappears

MQTT does not define registers, coils, node IDs or units. Those still have to be mapped. It is a transport for already-structured data.

11. Where the gateway fits

Southbound

Modbus RTU/TCP, OPC UA, IEC 60870-5-104, DNP3, REST. The gateway is a client or master. It polls, browses or subscribes and normalises the answers.

Northbound

MQTT over TLS to IoT Core, usually through Greengrass. The gateway is a publisher. It batches, spools and sends.

A PLC controls equipment. A SCADA system supervises the plant. A historian stores time-series history. A gateway moves data between OT and IT. They are different jobs; one box may do more than one.

13. What to ask the vendor

  • Which protocol and physical layer: Modbus RTU, Modbus TCP, OPC UA, other?
  • For Modbus: unit/slave ID, IP/port or serial settings, and the register map.
  • Address convention: reference number or zero-based offset?
  • Function code and data type for every point.
  • Byte order and word order; signed or unsigned; float or integer.
  • Scale, offset, unit and rollover behaviour.
  • Which points are mandatory, which are optional, and how often they change.
  • A known-good value or capture to prove the interpretation.
  • Whether writes are needed; v1 is read-only.
  • Any gateway, firewall, connection limit or serial isolation requirement.
